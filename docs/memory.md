# 记忆怎么放

搜魂管理的是 Grok Bot 存在云端的那份记忆，不是聊天记录，也不是人设和技能。

## 两条轴

写入前要定两件事。

| 界面 | 含义 | Bot 实际写入的类型 |
|---|---|---|
| 账号共用 · 指令 | 这个用户的所有 Bot 都会用 | `shared_profile` |
| 账号共用 · 普通事实 | 所有 Bot 用到才回忆 | `shared_journal` |
| 仅此 Bot · 指令 | 只有当前这个 Bot 会用 | `profile` |
| 仅此 Bot · 普通事实 | 只有当前这个 Bot 用到才回忆 | `journal` |

界面发给 Bot 的仍是 `scope`（`user` 或 `agent`）和 `tier`（`profile` 或 `log`）。Bot 自己换成上面的类型。这套对应是 Bot 的自述，安装包里没有参数表可以核对。

列表里每条前面的标签：

| 标签 | 范围 |
|---|---|
| 账号共用 | `user` |
| 仅此 Bot | `agent` |
| 团队 | `team` |
| 未标明 | 这次回复没给出范围 |

## 读写走哪条路

```
搜魂
  │
  ├─ 列出 Bot、确认登录     直接调用 Grok Bot 接口
  │
  └─ 拉取 / 写入 / 忘掉     给当前选中的 Bot 发一条对话
                              Bot 调用 UpdateMemory 或回忆工具
                              结果再从这条对话里取回
```

个人记忆没有一条桌面端能直接增删改的接口。`UpdateMemory` 和 `RecallMemory` 是 Bot 运行时的工具。

因此：

- 每次写入或忘掉，都会在那个 Bot 的对话里留下一条请求
- 拉取是让 Bot 导出，不是一个完整列表接口；一次最多按它能召回的量返回，没列完时界面会提示再拉
- 团队记忆不从这里写入。团队另有审核队列，个人 Bot 使用相关接口会被拒绝

## 不在这份记忆里的东西

人设、技能、例行任务和聊天记录都有自己的位置。搜魂不改它们。

以前没写成「账号共用」的事实，只有当时那个 Bot 能回忆。团队 Bot 另有一份摘要，和这里看到的个人记忆可能有时间差。
